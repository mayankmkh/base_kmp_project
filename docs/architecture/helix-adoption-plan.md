## 2. Role → convention plugin (21.1) and path rule

| Role (policy 9.0) | Plugin id | Path |
|---|---|---|
| app | `bkp.kmp.app` (shared KMP root), `bkp.android.app[.compose]`, `bkp.desktop.app`, `bkp.web.app` (shells) | `:app:*` |
| feature | `bkp.kmp.feature` | `:feature:*` |
| ui | `bkp.kmp.ui` | `:ui:*` |
| capability_api | `bkp.kmp.capability.api` | `:capability:*-api` |
| capability_impl | `bkp.kmp.capability.impl` | `:capability:*-impl` |
| foundation_api | `bkp.kmp.foundation.api` | `:foundation:*` |
| foundation_runtime | `bkp.kmp.foundation.runtime` | `:foundation:*` |
| platform | `bkp.kmp.platform` | `:platform:*` (no -api/-impl suffix) |
| platform_api | `bkp.kmp.platform.api` | `:platform:*-api` |
| platform_impl | `bkp.kmp.platform.impl` | `:platform:*-impl` |
| storage | `bkp.kmp.storage` | `:storage:*` |
| testkit | `bkp.kmp.testkit` | `:testkit:*` |
| (not validated as runtime edges) | — | `:tooling:*`, `build-logic` |

`bkp.kmp.lib` remains the internal base (targets DSL, Kotlin config, test baseline) applied by every KMP role plugin; it is no longer a primary plugin on its own. `bkp.kmp.lib.compose`, `bkp.kmp.feature.compose` and the FeatureBundle are removed. Compose is applied by the role plugins that need it (`app`, `feature`, `ui`, `foundation.api` only when the module opts in via `bkpModule { compose() }`).

Explicit API mode (21.5) is on for `capability.api`, `foundation.api`, `platform.api`, `ui`.

## 3. Graph validator (21.2) and stable rule IDs

Input: `config/helix/dependency-policy.json` = verbatim extraction of the Section 9.0 block (checked for drift against the master source by `checkHelixPolicySync`, rule `POLICY-DRIFT`). Exceptions: `config/helix/exceptions.json` (fields per 21.7: rule, scope, owner, reason, created, expires, removalCondition).

| Rule ID | Meaning |
|---|---|
| `DEP-ROLE-DENIED` | main-source project edge not allowed by the role matrix |
| `DEP-FEATURE-FEATURE-PUBLIC-PRESENTATION-ONLY` | feature→feature edge importing anything outside the target's `.api` package |
| `GRAPH-CYCLE-PHYSICAL` | project dependency cycle |
| `GRAPH-CYCLE-LOGICAL` | cycle after collapsing `*-api`/`*-impl` capability families |
| `MOD-ROLE-MISSING` / `MOD-ROLE-MULTIPLE` | module applies zero / more than one role plugin |
| `MOD-PATH-ROLE-MISMATCH` | role plugin does not match the module path |
| `FEATURE-PUBLIC-SURFACE-OUTSIDE-API` | top-level public declaration in a feature outside its `.api` package |
| `EXC-EXPIRED` | exception past its expiry date |
| `POLICY-DRIFT` | policy JSON differs from the master-source block |
| `STORAGE-MIGRATION-DUPLICATE` | SQLDelight migration version is repeated across schema-contributing modules |
| `STORAGE-MIGRATION-NAME` | SQLDelight migration file name is not a positive integer |

Failures print: rule id, offending module(s)/edge, one-line remedy.

## 4. Verification tiers (21.6)

`helix-kmp verify --fast --affected` / `--fast` / `--full` map onto Gradle umbrella tasks `verifyFast` / `verifyFull`; `--affected` narrows to modules changed vs. the merge base (git diff) plus their dependents. Fast = JVM compile + JVM/common tests + `checkModuleGraph` + detekt/spotless + Koin graph test. Full = fast + Android debug assemble + iOS simulator framework link + wasmJs browser bundle.

## 5. Execution phases (29.5)

1. build-logic: role plugins, validator, policy/exception files, plugin tests.
2. Foundation/platform/storage/ui moves plus new `:foundation:resource`, `:foundation:presentation`, `:foundation:runtime`.
3. `:capability:posts-api/-impl` + `:feature:posts` reference slice; delete `arch:core`, old features, `libs:posts`.
4. `:app:*` composition root and shells; iOS script path.
5. Control plane P0: `tooling/helix-kmp`, `AGENTS.md`, Skills, docs, adoption record; P1 thin commands only if time allows.
6. Verification: `./gradlew check`, debug assembles, iOS framework link, web bundle; evidence report (22.13).
